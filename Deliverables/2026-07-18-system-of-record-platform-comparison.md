# Off-the-shelf ClickUp replacement: wiki + tables + DB, agent-first — comparison brief

## Executive summary

No off-the-shelf platform cleanly delivers all three (wiki prose, genuine structured tables, and a real underlying database) *plus* mature, official multi-agent API/MCP access *plus* a clean data-loss record. Every strong candidate trades on at least one axis. The tightest single-platform picks are **AppFlowy** (genuinely open-source, self-hosted, real Postgres-backed database + docs, but young reliability track record and only community MCP servers) and **Notion** (best blended wiki+table+DB feel with an official hosted MCP and huge ecosystem, but 100% cloud, blocks-based pseudo-database that degrades past ~2–3K rows with rollups, and a hard 3 req/sec API ceiling that will bite multiple concurrent AI agents). **Outline** deserves a close look as a hybrid path: it is the most technically mature agent-access story of any candidate (first-party built-in MCP server since Feb 2026, 8-year-old REST API, Postgres backend) but it is a wiki, not a table/DB tool — it would need to be paired with real Postgres tables (which the team already runs via Supabase) rather than trusted alone for structured data.

## Key findings

1. **No candidate has a first-party MCP *and* a genuine relational database *and* a clean self-host story simultaneously.** Confidence: **High** (cross-checked across official docs/changelogs for each platform — Notion, Atlassian, Outline, Coda).
2. **Notion's "database" is a block-graph, not a relational table.** Every row is a page/block in a single Postgres store; official guidance and multiple independent write-ups agree performance degrades noticeably at 2,000–3,000 rows with rollups/formulas, severely beyond 10–20K rows, even though the nominal cap is 250,000 rows. Confidence: **High** (Notion's own help center + Notion Mastery + ONES.com + latwy.co all converge on the same degradation pattern).
3. **Confluence's "databases" feature (2024–25) is real but weak** — no formulas, no SUMIF, limited data types, one-way Jira sync only. It is closer to a structured-table bolt-on than a true DB. Confidence: **Medium** (Atlassian's own support docs + gocapable.com + stiltsoft.com agree; no independent benchmarking found).
4. **Official/first-party MCP servers exist for Notion (hosted, GA), Atlassian/Confluence (Rovo, GA Feb 2026), Coda (beta), and Outline (built-in, Feb 2026).** AppFlowy and Affine currently rely on **community-maintained** MCP servers only — not vendor-shipped. Confidence: **High** (verified against each vendor's own docs/changelog/GitHub org).
5. **Confluence has the worst documented history of extended, consequential outages among the SaaS candidates**, including a widely-reported multi-week 2022 Jira/Confluence outage where some customers had no backups of critical documents, and a 2025 AWS-linked Atlassian Cloud incident. Notion's incident history is high in *volume* (~488 tracked outages over ~6 years per StatusGator) but these read as mostly short degradations/rate-limit errors rather than permanent data loss — no credible report of Notion losing committed data outright turned up in this pass. Confidence: **Medium** (status-aggregator data + one long-form journalism piece — The Pragmatic Engineer — for the Atlassian incident; single-source-per-incident, not independently triangulated beyond status pages).
6. **AppFlowy and Outline are the only two candidates whose backend is plain Postgres** — directly compatible with the team's existing Supabase/Postgres literacy, meaning Silas/Mack could, if needed, read/write structured tables straight against the underlying schema rather than trusting only the vendor's API surface. Confidence: **High** (AppFlowy's own architecture blog + docs; Outline's documented Node+Postgres+Redis+S3 stack).
7. **Rate limits are a real constraint for a multi-agent write workload.** Notion: ~3 req/sec/integration (workspace-shared across all connections); hosted MCP capped at 180 req/min, search at 30 req/min. Confluence Cloud is moving to a points-based quota model from March 2026. Coda enforces per-token limits with async writes (poll for completion). None of these were designed for several autonomous agents hammering writes concurrently — all will need a queue/backoff layer regardless of platform chosen. Confidence: **High** (each vendor's own developer docs).

**Also surveyed, ranked out (weaker fit, kept brief):**
- **Nuclino** — no API access at *any* price tier per current comparison sources; disqualifying for an agent-write requirement. (Medium confidence, single comparison-site source — worth a direct vendor-doc check before fully ruling out.)
- **Slite** — API gated to Premium+ tier; positions itself as "AI-native" via conversational search, but no MCP server found in this pass; thinner ecosystem than the top 6.
- **SiYuan** — genuinely strong block-referencing/bidirectional-link PKM engine with a local API, but built and marketed for personal use, not a team multi-agent system of record; thin evidence of enterprise-grade reliability at team scale.
- **Obsidian + Bases/Publish** — Bases (shipped as a core plugin in early 2026) turns notes into database-like views, but it's a **local, client-side** feature; a plugin-level API for querying Bases results is still an open feature request on Obsidian's own forum as of this research, not a stable multi-agent write surface.
- **Tana / Anytype** — both ship genuinely interesting **local MCP servers** (Anytype's converts its OpenAPI spec to MCP tools; Tana's Local API exposes an MCP endpoint) but both are personal-outliner-first products without the team governance/roles layer a shared system of record needs.

## Top-2 recommendation

**#1 — AppFlowy (self-hosted).** The only candidate that is simultaneously a real wiki, a real (Postgres-backed) database with genuine table/board/grid views, fully open-source, and runs on infrastructure the team already operates (Postgres, optionally Supabase itself, S3-compatible storage). **Killer caveat: its MCP layer is entirely community-built, not vendor-shipped, and its production reliability history (documented 2025 mobile sync-drop issues) is the youngest and least battle-tested of the top 3.** Treat any AppFlowy MCP server as something Vex/Silas vet and pin, not something to trust blind on day one — and budget for a shakeout period before treating it as the system of record for anything load-bearing.

**#2 — Notion.** The most mature, best-documented, best-supported agent-access story of any hosted SaaS candidate (official hosted MCP, deep API, enormous integration ecosystem, no credible reports of outright data loss found). **Killer caveat: it is not actually a database.** Every "table" is a graph of blocks in Notion's own Postgres, and independent sources converge on real performance collapse once a table carries meaningful rollups/formulas past a few thousand rows — exactly the shape a build-management system of record will grow into. It is also 100% cloud with a hard per-integration rate ceiling (3 req/sec) that will directly throttle multiple concurrent AI agents unless a shared queue/backoff layer is built in front of it, and there is zero self-host or data-ownership fallback beyond periodic exports.

**Worth flagging as an honest aside, not a recommendation to build:** this brief was scoped to off-the-shelf platforms per Larry's ask, but the strongest *technical* combination surfaced by this research is not a single off-the-shelf product — it's Outline (best agent-access maturity: first-party MCP, mature 8-year API) sitting on the *same* Postgres the team already runs via Supabase, with real structured tables built directly in that Postgres rather than trusted to any vendor's "fake" database layer. That's outside today's off-the-shelf scope, but it's the sharpest data point this research turned up and is worth a deliberate build-vs-buy conversation with Nolan/Silas rather than defaulting past it.

## Methodology

Web search across each platform's own docs/changelog/GitHub, third-party 2026 comparison sites, and status-page aggregators, prioritizing primary sources (vendor docs, GitHub, official changelogs) over secondary write-ups. Search order: broad category survey → per-platform structure/API/MCP → per-platform reliability/outage history → pricing/self-host confirmation. No hands-on testing was performed (desk research only, per the brief's scope and time budget).

## Limitations

- Data-loss/reliability evidence for most platforms comes from status aggregators, community forums, and comparison-site summaries rather than primary incident post-mortems — flagged per-finding above where confidence is Medium rather than High.
- AppFlowy's and Affine's MCP/reliability picture is the fastest-moving of the set; both shipped meaningful changes within the last few months of this research and could shift again quickly.
- Nuclino's "no API" claim rests on one comparison-site source and was not cross-checked against Nuclino's own site — worth a 5-minute direct verification before treating as settled.
- No pricing/reliability data was independently verified beyond what vendors and secondary sources publish; none of this was load-tested against the team's actual agent-write volume.
- This brief does not cover data migration effort *out of* ClickUp into any of these platforms — that's a separate research pass if a direction is chosen.

## Recommendations

1. Before committing spend, run a **1–2 week AppFlowy self-hosted pilot** (Silas stands up the Docker stack; Mack wires the community MCP; Vex reviews it before any real data goes in) to pressure-test the reliability claims above directly rather than trusting secondary sources.
2. In parallel, have Nolan/Silas scope the **"Postgres-you-already-run + Outline-for-wiki" hybrid** as an explicit build-vs-buy alternative — it scored highest on agent-access maturity and reliability of everything surveyed, at the cost of being two components instead of one.
3. If neither pilot survives contact, Notion is the safe, well-supported fallback — but budget for a table-restructuring/sharding discipline from day one so it never crosses the ~2–3K-row rollup-heavy threshold that degrades it.
4. Do a 5-minute direct-vendor check on Nuclino's API claim and Slite's current MCP status before fully ruling either out — both were single-sourced in this pass.
