# AMENDMENT 4 — 2026-08-05. **DEFECT FOUND IN LIVE USE AT THE INTEGRATED HEAD**

**Found by Larry using the tool, not by the suite. All 437 governor tests are green over this.**

## The defect

**`--refresh` writes `recommendation.json` INTO the same directory the health-sample resolver scans**, and when it is the newest file there the resolver selects it **as a health sample**, finds no context fields, and renders `BLIND`.

**Reproduced deterministically:**

```
$ node tools/governor/footer.mjs --refresh
footer: recommendation refreshed — next: Opus/high (matched:Opus/high+Sonnet/medium+Sonnet/low)

$ node tools/governor/footer.mjs
⟦GOV⟧ ctx -- · BLIND · NO ADVICE · next: Opus/high · CONTINUE      ← number GONE

$ touch ~/.mypka/governor/health/<project>/recommendation.json
$ node tools/governor/footer.mjs
⟦GOV⟧ ctx -- · BLIND · NO ADVICE · next: Opus/high · CONTINUE      ← reproduced on demand
```

Three renders immediately before and after were `⟦GOV⟧ ctx ~39% (389k/1000k) · GREEN`, so the number is present whenever a real sample happens to be newer.

## Why it matters more than a transient

**Every render in the window between a `--refresh` and the next statusLine sample loses the context number.** A refresh fires on exactly the five events Warwick named — frontier change, next Work Order change, phase boundary, context threshold, handback state — **so the number disappears precisely when he is most likely to look, and it comes back on its own, which makes it look like a glitch rather than a defect.**

**It defeats WP-3B(a) — the measured number — at the moment the recommendation becomes most useful.**

## Why the suite did not catch it, and this is the lesson

**The tests redirect the store via `MYPKA_GOVERNOR_HEALTH_DIR`, so the cache and the samples never collided under test.** The two artefacts only share a directory in real use. **This is E-F's lesson in a second costume: a fault that only exists in the interaction between two things, invisible to every test that exercises them apart.**

## Required

1. **Fix at source: the cache must not live in the sample directory.** Preferred — write it beside the store rather than inside the scanned path. **A name-based exclusion in the resolver is a filter that can silently decay and is second choice; if you take it, say why.**
2. **A regression test that reproduces the collision — cache newest in the scanned directory — and asserts a real sample is still selected.** It must fail against the current code; show it red, then green.
3. **Mutation-prove it** as you have the others.
4. **Re-run the full governor set** and report counts.

**`file_surface` unchanged. If the correct fix is outside it, return and say so — do not widen it yourself.**

**This is not a criticism of the build.** Larry asked for a demonstration and the demonstration found it, which is the system working. **It is, however, evidence for the phase report that a green suite plus a redirected store is not the same as a proven product.**
