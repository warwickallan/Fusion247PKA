## 3. The dispatch path, TRACED FROM SOURCE

### 3.1 What actually issues a Work Order

`tools/wo/envelope.mjs` **generates** an order file. It is not on the dispatch path at all:

- `tools/wo/envelope.mjs:870` — `ORDER_MARKER = 'GENERATED by tools/wo/envelope.mjs'`, and its
  own comment at `:864` says *"the provenance header is evidence of origin — NOT a checker
  service… this tool does not police itself."*
- `tools/wo/envelope.mjs:920` `countMarkers()` and `:1630` the `--count-markers` CLI branch —
  the only pre-existing readiness signal. It counts two literal strings. It returns
  `ready: authorCount === 0 && unresolvedCount === 0` and **exits 0 unconditionally**.
- `tools/wo/README.md:3` states the honest position outright: *"That is issuer discipline +
  worker REFUSE of unmarked orders — **not** an auto-invoking daemon, SessionStart hook, or
  control plane."*

`Team Knowledge/SOPs/SOP-022-work-order-preflight.md:299–309` confirms the same shape: the
issuer *should* generate, the worker *should* refuse an unmarked order. **Both halves are
habits.** Nothing executes between "Larry decides to dispatch" and "the worker starts".

**Conclusion: the real production event is the host's subagent-dispatch tool call.** There is
no CLI, script, wrapper or queue in this repository that a dispatch passes through. The
Work Order text is carried in the tool call's `prompt`.

- `tools/governor/worktree-guard.mjs:47` — `GUARDED_TOOLS` mirrors that matcher. **`Task` is

**So the mechanism to make dispatch refuse already exists and is already proven in

## 8. What is NOT proven

1. **That the control fires in production.** §6. The single most important gap, and it is
   structural, not an oversight.
2. **That the shape check cannot be tripped by an honest non-order dispatch.** It requires
   the words "work order" plus an envelope field name, or two envelope field names. A future
   research brief *about* Work Orders would be denied. Cost: one message. Direction chosen
   deliberately — a false deny costs a restatement, a false allow loses the gate.
3. **That every under-authored order is caught.** It is not. Known holes, stated rather than
   implied: an acceptance criterion naming its target as a bare filename (`runtime.js`) or a
   partial path (`packet/x.js`) is invisible to the AC check, because widening it refused a
   correctly-amended real order; a free-form dispatch using none of the envelope vocabulary
   is not Work-Order-shaped and passes; and semantic *correctness* of an outcome, a
   contradiction between two acceptance criteria, or a wrong `governance_head` are all
   outside what any of this examines. **The worker read-back remains the reality gate. This
   gate only stops orders that are structurally unexecutable.**
4. **The fail-open direction.** An internal error in the guard DEFERS (matching
   `worktree-guard.mjs` AD-19). While the guard is broken it is also silent. That is a real
   cost and it is chosen, not overlooked — a guard that bricks every dispatch when it has a
   bug is removed within a day, and a removed control protects nothing.
