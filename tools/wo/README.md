# Work Order envelope generator — ordinary dispatch route

**J1-1 (honest form):** the **ordinary** way to issue a Work Order is to run this generator, author bare slots, recompute markers, then dispatch. That is **issuer discipline + worker REFUSE of unmarked orders** (SOP-022) — **not** an auto-invoking daemon, SessionStart hook, or control plane. Capability is this CLI; the route is complete when Larry uses it every time and workers refuse anything else.

```bash
# Produce a complete order (repo surfaces)
node tools/wo/envelope.mjs \
  --owner keel \
  --governance-head "$(git rev-parse HEAD)" \
  --worktree "$(pwd)" \
  --branch "$(git branch --show-current)" \
  --surface 'tools/wo/**' \
  --out Deliverables/proofline/WO-….md

# Machine-install order (G-6) — absolute paths only; live_authority deviation required
node tools/wo/envelope.mjs \
  --owner mack \
  --governance-head "$(git rev-parse HEAD)" \
  --machine-surface 'C:/Users/Buggly/.mypka/governor/ding.mjs' \
  --deviate 'live_authority=BOUNDED — ~/.mypka/governor/** only' \
  --deviation-authority 'Warwick, YYYY-MM-DD' \
  --out Deliverables/proofline/WO-….md

# After Larry authors bare slots — live readiness (G-5)
node tools/wo/envelope.mjs --count-markers Deliverables/proofline/WO-….md

# SEMANTIC readiness (4F CAPA). Exit 0 = READY, 1 = NOT READY. Run this before dispatching.
node tools/wo/envelope.mjs --assess Deliverables/proofline/WO-….md
```

Workers REFUSE orders that lack the `GENERATED by tools/wo/envelope.mjs` marker (SOP-022). Exit codes of this tool are **not** verdicts about any order — **except `--assess`, which is exactly that and nothing else.**

## The 4F CAPA readiness gate — what is BUILT and what is NOT WIRED

**The defect (Warwick, 2026-08-09):** `--count-markers` returned `ready: true` for an order whose five test paths were granted in `contract_basis` — a field that *justifies* a surface and does not *grant* one. **The gate validated the presence of markers, not executable semantics.**

**`--assess` checks, in one pure function over one file:**

| Check | Fails when |
|---|---|
| `not-generated` | the body carries no `GENERATED by …` marker (SOP-022 class A) |
| `blank-markers` | any `AUTHOR REQUIRED` or `UNRESOLVED` marker survives |
| `missing-mandatory-field` | an envelope field from the canonical template is **ABSENT** (no such key) or **EMPTY** (key present, no value) — the two are labelled separately, because the fixes differ |
| `malformed-field` | an envelope field is present and populated but in the **wrong shape** — e.g. `document_impact: [] …prose…`, which parses as a string, so every reader downstream silently sees nothing. The message says what shape was expected and what was found |
| `missing-runbook-path` | `operational_handoff: mack` with no `runbook_path` |
| `no-writable-surface` | neither `file_surface` nor `machine_surface` grants anything |
| `basis-surface-not-granted` | **the row-6 defect** — `contract_basis` cites a surface `file_surface` does not grant |
| `no-acceptance-criteria` | the `## Acceptance criteria` section is empty |
| `ac-path-not-granted` | an acceptance criterion names a repository implementation target absent from `file_surface` |

The mandatory field list **and each field's expected shape** are **read from `Team Knowledge/Templates/work-order.md`**, never restated here.

**Every refusal names its specific offender.** `"order not ready"` is not an output this tool can produce: each failure line carries the exact field, surface or path at fault, and the enumeration is pinned in `dispatch-guard.test.mjs` / `envelope.test.mjs` so a rejection cause cannot be added without a diagnostic test.

**`dispatch-guard.mjs` is CAPA item 8** — a `PreToolUse` hook for the `Task` (subagent dispatch) tool. It denies a dispatch that carries an unready order, and denies a dispatch that is Work-Order-shaped while carrying no generated order at all (the "send a worker directly" bypass). Everything else defers silently.

### ⛔ It never puts a prompt in front of Warwick (Warwick, 2026-08-09)

> *"This is an internal delegation-quality control, not a Warwick approval gate. It must never require me to click/approve routine dispatches."*

The host's `permissionDecision` vocabulary is `allow` · `ask` · `deny` (established by reading `tools/governor/worktree-guard.mjs`, which uses `ask` deliberately to reach Warwick). **This guard's enum contains neither `ask` nor `allow`:** it denies, or it stands aside. Emission goes through a frozen map *and* a frozen permitted-set check, so an unpermitted value costs a **missed refusal, never a prompt** — the fail direction is silence.
